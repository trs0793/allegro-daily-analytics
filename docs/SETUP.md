# Подключение Allegro

## 1. User-Agent — текущий шаг

В [генераторе Allegro](https://apps.developer.allegro.pl/user-agent) заполните:

| Поле | Значение |
| --- | --- |
| Wybierz aplikację | Выберите зарегистрированное приложение Allegro Daily Analytics |
| Wersja aplikacji | `1.0.0` |
| URL dokumentacji | Публичный адрес ниже |

https://github.com/trs0793/Automated-reporting-in-Airflow/blob/main/docs/allegro-daily-analytics.md

Нажмите **GENERUJ USER-AGENT**. Сохраните полную полученную строку: в коде нужно использовать именно результат генератора. Не конструируйте имя и строку вручную и не меняйте их после настройки; версия меняется при выпуске новой версии приложения.

Ссылка на документацию должна открываться без доступа к приватному репозиторию. Ссылка на этот закрытый репозиторий для данной цели не используется.

## 2. Подключение аккаунта

Следующий этап — реализация OAuth для типа приложения, выбранного при регистрации.

Перед реализацией проверьте тип на странице приложения:
- **Device Flow:** подтверждение входа по ссылке и коду; сервер обратного перенаправления не требуется.
- **Authorization Code:** вход через браузер и возврат на зарегистрированный redirect URI.

Метод должен соответствовать фактическому типу приложения. Этот документ не подтверждает, что OAuth уже настроен.

Client ID и Client Secret задаются оператором в локальной конфигурации или хранилище секретов среды запуска. Их не нужно публиковать в README, коммитах, Issues или пересылать в чат.

После авторизации проверяется запрос `GET /me`, затем разрешения на чтение заказов и расчётов. Успешный доступ к профилю сам по себе не подтверждает доступ ко всем данным.

## 3. Первая проверяемая выгрузка

Сначала выполняется ручной запуск за ограниченный период и сверка с кабинетом Allegro:

1. Проверить аккаунт и разрешения.
2. Получить заказы и начисленные комиссии с обработкой всех страниц ответа.
3. Сохранить записи с устойчивыми идентификаторами и временем обновления.
4. Повторить загрузку без дублирования, проверить статусы и корректировки.
5. Убедиться, что даты и валюты обработаны правильно.

После успешной сверки выбираются постоянное место запуска и хранения данных, настраиваются обновление токенов, расписание и уведомления об ошибках. Расписание сейчас не создано.
